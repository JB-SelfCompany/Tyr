## Project Overview

Tyr is an Android application that provides true peer-to-peer email using the Yggdrasil network. It runs a complete Yggmail server (Rust-based native library via UniFFI) on the device and exposes standard SMTP/IMAP protocols on localhost for email clients like DeltaChat. It also includes a built-in chat interface for direct P2P messaging.

**Key Technologies:**
- **Language**: Kotlin 2.2.20
- **Min SDK**: 23 (Android 6.0), **Target SDK**: 33, **Compile SDK**: 36
- **Native Library**: Rust (`libyggmail_mobile.so`) with UniFFI Kotlin bindings + JNA 5.14.0, located in `jniLibs/` (per-ABI `.so` files) and `uniffi/yggmail_mobile/` (auto-generated Kotlin)
- **UI**: XML layouts with View Binding, Material Design 3
- **Security**: Android Keystore with EncryptedSharedPreferences (AES-256-GCM)
- **Background Tasks**: AlarmManager for Doze-compatible periodic maintenance
- **QR Codes**: ZXing library (3.5.3) for mailto: link generation/sharing and camera-based scanning

### Native Library (Rust + UniFFI)
The native library is a Rust crate compiled to shared objects per ABI in `app/src/main/jniLibs/`. UniFFI auto-generates the Kotlin bindings at `app/src/main/java/uniffi/yggmail_mobile/yggmail_mobile.kt` — **do not edit this file manually**.

To rebuild the native library and bindings (typically done in the `Library/yggmail/` sibling repo):
1. Rebuild the Rust crate with `cargo build` targeting Android ABIs
2. Run `uniffi generate` to regenerate Kotlin bindings
3. Copy `.so` files to `jniLibs/{abi}/` and the generated `.kt` to `uniffi/yggmail_mobile/`

### ProGuard / R8
Release builds use minification. Critical keep rules in `app/proguard-rules.pro`:
- `uniffi.yggmail_mobile.**` — all UniFFI bindings
- `com.sun.jna.**` — JNA runtime
- `com.jbselfcompany.tyr.data.**` — data classes used by native code
- Native methods must not be stripped

## Architecture

### High-Level Structure

```
UI Layer (Activities/Fragments) → Service Layer (YggmailService) → Native Layer (Rust via UniFFI/JNA)
                    ↓                            ↓
            Data Layer                   Chat Layer (SMTP/IMAP via localhost)
   (ConfigRepository + SecurePreferences)   (ChatRepository + SmtpSender + ImapFetcher)
```

### Core Components

**1. YggmailService** (`service/YggmailService.kt`)
- Foreground service wrapping the native Yggmail library
- Runs SMTP (127.0.0.1:1025) and IMAP (127.0.0.1:1143) servers
- Uses `HandlerThread` (`serviceThread`) for all blocking native calls — **never call native methods from UI thread**
- Uses `serviceScope` (CoroutineScope + `Dispatchers.IO`) for I/O-bound operations (IMAP polling, DB access)
- Background chat polling every 2 minutes on `chatPollHandler` (same `serviceThread` looper)
- Static `instance` field for direct API access (e.g., `YggmailService.instance?.sendChatMessage(...)`)
- Status updates via `ServiceStatusListener` interface

**Native Library Integration (UniFFI):**
```kotlin
import uniffi.yggmail_mobile.YggmailMobile
import uniffi.yggmail_mobile.YggmailConfig
import uniffi.yggmail_mobile.YggmailState

val config = YggmailConfig(
    privateKey = "", peers = peersList, listen = emptyList(),
    groupPassword = "", databasePath = dbPath,
    smtpPort = 1025u, imapPort = 1143u, passwordHash = sha256Hex
)
val mobile = YggmailMobile()
mobile.setPassword(password)
mobile.start(config)
mobile.startSmtp(1025u, passwordHash)
mobile.startImap(1143u, passwordHash)
val state = mobile.getState()          // returns YggmailState with address, publicKey
mobile.setActive(active)               // power state hints for adaptive keep-alive
mobile.setCharging(charging)
mobile.updatePeers(peersJsonArray)     // hot-reload peers without restart
mobile.getPeerConnectionsJson()        // JSON array of peer connection info
mobile.getMailStorageStats()           // storage usage
mobile.stop()
```

**2. Chat Subsystem** (`chat/`)
- Built-in P2P chat using the same SMTP/IMAP servers as DeltaChat
- Messages distinguished by `X-Tyr-Chat: 1` header (vs DeltaChat's DCMESSAGE headers)
- **SmtpSender** (`chat/network/SmtpSender.kt`): Plain-SMTP client on localhost:1025, supports MIME multipart attachments, delivery/read receipts (`X-Tyr-Read-Receipt`, `X-Tyr-Delivery-Timestamp`), sender nicknames (`X-Tyr-Nickname`)
- **ImapFetcher** (`chat/network/ImapFetcher.kt`): Plain-IMAP client on localhost:1143, filters for `X-Tyr-Chat: 1` headers, streams large literals (>512KB) to temp files to prevent OOM on big attachments
- **ChatRepository** (`chat/data/ChatRepository.kt`): SQLite-backed storage for contacts and messages (`tyr_chat.db`, version 6)
- **ChatDbHelper** (`chat/data/ChatDbHelper.kt`): Schema with `contacts` table (address, name, is_pending, is_declined) and `messages` table (imap_uid, from/to, body, status, attachment fields)
- **ChatFragment** (`chat/ui/ChatFragment.kt`): Contact list with unread badges
- **ConversationActivity** (`chat/ui/ConversationActivity.kt`): Message thread view with attachment support
- **Message status flow**: `SENDING` → `SENT` (delivery receipt) → `READ` (read receipt)
- **IMAP UID watermark**: `ConfigRepository.advanceLastSeenImapUid()` prevents re-fetching old messages after contact deletion — watermark only advances, never decreases

**3. ConfigRepository** (`data/ConfigRepository.kt`)
- Central configuration management using SharedPreferences (`tyr_config`)
- Password encrypted via Android Keystore (`SecurePreferences` → `tyr_secure_prefs`)
- Peer management: v2 format with enabled/disabled state per peer (`PeerInfo`)
- Migrates legacy plaintext passwords and old peer formats automatically
- Key methods: `getPeersString()`, `getPassword()`, `saveMailAddress()`, `getAcceptMessagesFromNonContacts()`, `advanceLastSeenImapUid()`

**4. MainActivity** (`ui/MainActivity.kt`)
- Service control (start/stop), mail address display, server info, status binding
- DeltaChat integration via DCLOGIN URLs and AutoconfigServer (localhost:8888)
- QR code generation/scanning for mailto: links with sharing
- Bottom navigation: Home, Chat, Settings tabs
- Does NOT call `setAppActive(false)` on pause — allows DeltaChat to remain active

**5. TyrApplication** (`TyrApplication.kt`)
- Application singleton (`instance`), holds `configRepository`
- Creates three notification channels: `CHANNEL_ID_SERVICE` (min priority), `CHANNEL_ID_MAIL` (default), `CHANNEL_ID_CHAT` (high priority)
- Network callback registration delayed 15 seconds after startup for battery optimization

**6. BackupManager** (`utils/BackupManager.kt`)
- Encrypted `.tyrbackup` files: AES-256-GCM with PBKDF2 (100k iterations)
- Format: `[32-byte salt] + [12-byte IV] + [encrypted JSON payload]`
- Can include `yggmail.db` (Ed25519 keys) and `tyr_chat.db` (chat history)

**7. MaintenanceReceiver** (`receiver/MaintenanceReceiver.kt`)
- AlarmManager-based periodic maintenance (every 15 min, Doze-compatible via `setExactAndAllowWhileIdle`)
- Checks peer connectivity and triggers reconnection if no peers are up
- Cancels when service stops

### Data Storage

| Store | File | Purpose |
|-------|------|---------|
| SharedPreferences | `tyr_config` | Onboarding, peers (v2 JSON), mail address, public key, service flags, UI prefs, IMAP UID watermark |
| EncryptedSharedPreferences | `tyr_secure_prefs` | Password (AES-256-GCM via Android Keystore) |
| SQLite | `yggmail.db` | Ed25519 keys, message storage, peer state (managed by native library) |
| SQLite | `tyr_chat.db` | Chat contacts + messages (managed by ChatDbHelper, version 6) |

### Battery Optimization

The app implements sophisticated battery management:
- **Operation-based WakeLocks**: Brief WakeLocks only for critical operations (not held continuously)
  - Message send: 30-second timeout
  - Shutdown: 20-second timeout
- **Periodic maintenance**: AlarmManager-based tasks every 15 minutes (Doze-compatible)
- **Power state awareness**: Native library receives charging/dozing/active state for adaptive behavior
  - QUIC keep-alive: 60s on battery, 15s when charging, 5s when active
  - IMAP heartbeat: 3-29min on battery, more frequent when charging
- **Doze Mode handling**: Forces immediate peer reconnection when exiting Doze (keep-alive transition closes connections)
- **Debounced network callbacks**: 1-second debounce on network changes; startup grace period (5s) suppresses early reconnects
- **Low-priority service notification**: `PRIORITY_MIN`, no badge, no timestamp

### Lifecycle Management

**Boot Flow:**
1. `BootReceiver` receives `BOOT_COMPLETED`
2. Checks: onboarding complete + autostart enabled + service enabled
3. If true: starts `YggmailService`

**First Run:**
1. App checks `!configRepository.isOnboardingCompleted()`
2. Shows `OnboardingActivity` (3 steps: Welcome → Password → Peers via ViewPager2)
3. On completion: saves config and transitions to `MainActivity`

**Network Changes:**
- `NetworkChangeReceiver` monitors WiFi/cellular/ethernet changes (ConnectivityManager callback)
- Debounced to prevent reconnection storms
- Sends `ACTION_RECONNECT_PEERS` to service after startup grace period

## Development Guidelines

### Working with Native Library (UniFFI)

**Thread Safety:**
- ALL native Yggmail calls must happen on the service's `HandlerThread` (`serviceHandler.post { }`)
- Never call native methods from UI thread (will block the app)
- Synchronous wrappers use `CountDownLatch` with timeouts (5-15s typical)

**Lifecycle:**
- Always call `mobile.setPassword()` before `mobile.start()`
- Always call `mobile.stop()` before releasing the instance
- `softStop()` gracefully disconnects peers first (calls `updatePeers("[]")` then `stop()`)
- All stop/close operations are timeout-protected

**Hot Reload:**
- `hotReloadPeers()` — live peer update without service restart via `updatePeers(jsonArray)`
- `hotReloadPassword()` — password update via `setPassword()` on running service

### Chat Subsystem Architecture

The chat layer communicates with the Yggmail SMTP/IMAP servers on localhost:
```
ConversationActivity → SmtpSender (localhost:1025) → Yggmail SMTP → Yggdrasil network
YggmailService (poll) → ImapFetcher (localhost:1143) → Yggmail IMAP → ChatRepository → UI
```

**Message flow:**
1. User types message in ConversationActivity
2. SmtpSender sends via plain SMTP with `X-Tyr-Chat: 1` header
3. Background poll (every 2 min) fetches new messages via ImapFetcher
4. Messages filtered by `X-Tyr-Chat: 1`, matched against contacts
5. New messages stored in `tyr_chat.db`, notification shown, broadcast sent
6. Delivery/read receipts sent back automatically

**Adding new chat features:**
- New headers: Add to SmtpSender and ImapFetcher's companion constants
- New message fields: Add column to ChatDbHelper, bump `DB_VERSION`, add migration in `onUpgrade()`
- New UI: Add to `chat/ui/` package, extend `ChatFragment` or `ConversationActivity`

### Configuration Changes

When modifying settings:
1. Add getter/setter to `ConfigRepository` with SharedPreferences key constant
2. Add UI in `SettingsFragment` / `SettingsActivity`
3. Update backup/restore in `BackupManager` if persistent
4. Consider migration strategy for existing users

### Security Considerations

**Password Handling:**
- Always use `SecurePreferences` for password storage
- Password hash (SHA-256 hex) passed to native library for SMTP/IMAP auth
- Never log or display passwords in plaintext

**EncryptedSharedPreferences & Samsung Devices:**
- `SecurePreferences` implements automatic recovery for Android Keystore issues
- Known issue on Samsung Galaxy M-series (see [tink-crypto#535](https://github.com/google/tink/issues/535))
- On Keystore failure, corrupted master key and preferences are auto-deleted and recreated
- Thread-safe with `@Synchronized` annotation

**Key Management:**
- Ed25519 keys generated by Rust library on first `start()`
- Mail address derived from public key: `<64-hex>@yggmail`
- `clearKeys()` in ConfigRepository removes stored address/pubkey but does NOT delete `yggmail.db`

## Common Scenarios

### Adding a New Setting

1. Add key constant + getter/setter to `ConfigRepository`
2. Add UI in `SettingsFragment` (uses `SettingItem.Switch` / `SettingItem.List` pattern)
3. If needed in backup, update `BackupManager.createBackup()` and `restoreBackup()`

### Modifying Service Behavior

1. Make changes in `YggmailService`
2. Ensure all native calls use `serviceHandler.post { }`
3. Update status via `updateStatus()` for UI feedback
4. Test with service restarts and device reboots

### Debugging Native Library Issues

1. Enable log collection in Settings → Logs (`configRepository.setLogCollectionEnabled(true)`)
2. Check `LogsActivity` for native library logs (logged via `TyrLogger`)
3. Native crashes: Check `adb logcat` for NDK stack traces
4. Database issues: Inspect `yggmail.db` (SQLite format)

STARTING → RUNNING → STOPPING → STOPPED
